## Part 1｜主題課程：AI 的風險、隱私與治理框架

### 一、什麼是 AI 安全（AI Safety）

「AI 安全」指的是在設計、開發與部署 AI 系統時，確保其行為可預測、穩定可靠，並符合人類價值與法律規範，同時避免對個人或社會造成傷害。這不只是技術問題，也涉及倫理、法律與社會責任。管理上可以把 AI 安全拆成四個層次來理解：

**1. 功能安全（系統本身會不會出錯）**

| 案例 | 事件 | 管理啟示 |
|---|---|---|
| Uber 自駕車事故（2018，美國亞利桑那州） | 系統偵測到行人但分類錯誤，安全駕駛員未即時介入，成為全球首起自駕車致死案例 | AI 系統必須有備援機制與嚴格測試流程，不能只看模型平均準確率，要看「最壞情況」的表現 |
| Tesla 自動輔助駕駛 | 強調提升道路安全，但仍發生多起事故 | 「輔助」與「自動」的界線必須對使用者清楚溝通，避免過度信任（over-reliance） |

**2. 資安與對抗攻擊（系統會不會被惡意欺騙）**

影像辨識系統可能被「對抗樣本（adversarial examples）」欺騙——例如在停車標誌上貼幾片人眼幾乎看不出差異的貼紙，就能讓自駕車的模型把它誤判成限速標誌。生成式 AI 時代則出現「提示注入攻擊（Prompt Injection）」：攻擊者在輸入內容中夾帶隱藏指令，誘導語言模型洩漏系統設定或內部資料。企業導入生成式 AI 時，必須把「資料保護」與「權限控管」當成上線前的必要檢查項目，而不是事後補救。

**3. 內容安全（系統產出的內容會不會造成傷害）**

| 案例 | 事件 | 管理啟示 |
|---|---|---|
| Microsoft 聊天機器人 Tay（2016） | 上線後遭網友刻意誘導發表極端與不當言論，24 小時內下架 | 具持續學習能力的系統，上線前必須建立內容過濾與監督機制，不能假設使用者都會善意互動 |
| 深偽（Deepfake）技術濫用 | 被用於語音詐騙、政治人物假影片，影響社會信任與民主制度 | 生成式 AI 的「以假亂真」能力，需要搭配內容溯源、浮水印等技術對應 |

**4. 前沿安全（更長期、更根本的問題）**

當大型語言模型與 AI 代理人能自主規劃並執行多步驟任務時，會出現更高層次的問題：如何確保 AI 的目標與人類意圖一致（目標對齊）？如何避免模型被濫用於惡意用途？這類「前沿安全」議題目前仍在快速發展中，是各國政府與國際組織建立 AI 治理框架的主要動機。

**風險分類的總結**：AI 的風險可分為**直接風險**（交通事故、醫療誤判、機器操作失誤）與**間接風險**（資訊操弄、隱私外洩、就業結構改變、社會不信任）。技術發展不應只追求效率，更要評估這兩類風險的長期社會影響。

### 二、隱私挑戰：從資料生命週期理解風險

AI 系統對資料的依賴，貫穿「蒐集 → 訓練 → 應用」三個階段，每個階段都有不同的隱私風險：

| 階段 | 風險情境 | 案例 |
|---|---|---|
| 資料蒐集階段 | 資料蒐集是否取得當事人同意？是否超出「必要範圍」？ | 醫院與科技公司合作開發診斷模型，需提供病歷資料（姓名、身分證字號、診斷結果），若未經同意即屬違法 |
| 模型訓練階段 | 模型是否「記住」了訓練資料中的個資，導致可被反推還原？ | 金融機構用客戶交易紀錄訓練風險評估模型，即使去識別化，跨資料源比對仍可能「再識別」出個人 |
| 應用╱部署階段 | 系統上線後持續蒐集的行為資料，長期累積會不會洩漏更多資訊？ | 智慧音箱蒐集語音指令、手機記錄定位、監視系統搭配人臉辨識蒐集影像——單筆資料看似平常，長期整合分析卻可能揭露生活模式、興趣甚至政治傾向 |

**關鍵概念｜準識別欄位（quasi-identifier）**：姓名、身分證字號是「直接識別欄位」，移除即可避免直接曝光身份；但性別、出生年月日、郵遞區號這類「準識別欄位」，單獨看無害，組合起來卻可能只對應到極少數人，一樣能被重新識別（這也是本週實作練習要體驗的重點）。

**隱私保護的技術工具：**

| 技術 | 做法 | 特性 |
|---|---|---|
| 去識別化 | 移除或遮蔽可直接辨識個人的欄位 | 最基本，但不足以防止透過準識別欄位比對還原身份 |
| 概化（Generalization）／k-匿名性 | 把精確欄位轉為區間或分類（如出生年月日→出生年） | 確保每個組合至少對應 k 筆以上紀錄，降低唯一識別機率 |
| 差分隱私（Differential Privacy） | 在統計結果或資料中加入數學上可控的隨機雜訊 | 讓「某一筆資料是否存在於資料集中」在統計上難以被推斷 |
| 聯邦學習（Federated Learning） | 資料留在使用者裝置或機構本地端，只共享模型參數 | 適合醫療、金融等資料不能離開機構的場景 |

**資料最小化原則**：只蒐集完成任務所必需的資訊，避免不必要的保存與二次利用。這是隱私保護技術以外，管理上最基本、也最容易被忽略的一道防線。

**台灣法規依據**：《個人資料保護法》要求資料蒐集須有特定目的，並保障當事人查詢、更正與刪除個人資料的權利，是企業導入任何 AI 應用前的基本合規門檻。

### 三、演算法偏誤與倫理

**偏誤從哪裡來？** 大致可分三個來源：

1. **資料偏誤**：訓練資料本身不具代表性，或反映了歷史上既存的不平等（例如過去男性主導的履歷資料）。
2. **演算法偏誤**：模型的優化目標或特徵選擇方式，放大了資料中原本就存在的差異。
3. **人為偏誤**：開發團隊在定義問題、選擇評估指標時，帶入了未被察覺的假設。

| 案例 | 事件 | 管理啟示 |
|---|---|---|
| Amazon 招聘 AI（2014） | 訓練資料多來自過去以男性為主的履歷樣本，系統將「男性特徵」視為較佳指標，對女性求職者評分偏低，計畫因此終止 | AI 並非天然中立，決策品質高度依賴訓練資料，導入前須做偏誤檢測 |
| COMPAS 再犯風險評估系統 | 用於協助法官量刑，後續研究發現系統將黑人被告評為高風險的比例顯著高於白人被告，即使未直接使用種族欄位 | 資料中的隱含關聯仍可能導致差別待遇，重大公共決策須有透明與審查機制 |
| ChatGPT 學術誠信爭議（2022） | 部分學生利用生成式 AI 代寫報告，難以辨識是否由人工撰寫，港大等校宣布限制課堂使用 | 生成式 AI 高度擬人化的產出，對既有制度（教育評量、著作權、責任歸屬）帶來衝擊 |

**「公平」怎麼量化？** 這是管理者常忽略、卻是稽核偏誤時最關鍵的一步。常見的公平性定義包括：

| 公平性定義 | 意義 | 上週實作對應 |
|---|---|---|
| 統計均等（Demographic Parity） | 不同群體被判定為「正向結果」的比例應該相近 | — |
| 假陽性率均等（Equalized False Positive Rate） | 不同群體「實際無風險卻被誤判為高風險」的比例應該相近 | 本課程 Colab 實作重現的正是這個指標——COMPAS 對黑人被告的假陽性率顯著高於白人被告 |
| 均等勝算（Equalized Odds） | 同時要求假陽性率與假陰性率在不同群體間都相近，是比前兩者更嚴格的標準 | — |

值得注意的是，這幾種公平性定義**彼此可能互相衝突**——滿足其中一種標準，往往就無法同時滿足另一種。這也是為什麼「演算法要不要公平」從技術問題變成需要管理階層做價值判斷的治理問題。

**黑盒子問題與可解釋性**：深度學習模型內部結構複雜，往往難以說明「為什麼做出這個判斷」，這在醫療、司法、金融等高風險領域會引發責任歸屬的爭議——如果連開發者都說不清楚模型為何誤判，企業要如何對受影響的當事人負責？

**責任歸屬的難題**：當 AI 系統造成損害時，究竟該由誰負責？以自駕車事故為例，可能牽涉軟體開發商（演算法是否有缺陷）、車輛製造商（硬體整合是否得當）、駕駛人（是否善盡監督義務）多方角色，責任難以單純歸因於一方。這正是各國積極立法的核心動機之一。

### 四、全球 AI 治理比較

| 規範／框架 | 性質 | 核心邏輯 |
|---|---|---|
| 台灣《個人資料保護法》 | 強制性法律 | 資料蒐集須目的明確化，當事人享有查詢／更正／刪除權 |
| 歐盟 *Artificial Intelligence Act*（2024 通過） | 強制性法律 | 風險分級管理：**不可接受風險**（例如社會信用評分，直接禁止）／**高風險**（如醫療、招聘、信用評分，須嚴格透明度與資料治理）／**有限風險**（如聊天機器人，須告知使用者正在與 AI 互動）／**最小風險**（多數應用，鼓勵自律） |
| 台灣《人工智慧基本法》（民國 115 年 1 月 14 日公布施行） | 強制性法律 | 詳見下方七大原則說明；中央由國家科學及技術委員會統籌，涉及特定產業則由該產業主管機關管理 |
| OECD AI Principles（2019） | 國際軟性準則 | 強調包容性成長、人本價值、透明度、穩健性與問責，是許多國家立法時參考的共同基礎 |
| NIST AI Risk Management Framework（美國） | 自願性框架 | 提供企業「治理—映射—衡量—管理」的風險管理循環，不具強制力，但常被採購合約引用為事實標準 |

**台灣 AI 基本法七大原則，逐一說明：**

| 原則 | 具體意涵 |
|---|---|
| 永續與福祉 | AI 發展應兼顧環境永續與社會整體福祉，不能只追求經濟效益 |
| 人類自主 | 保留人類對重大決策的最終判斷與否決權，AI 是輔助而非取代 |
| 隱私保護 | 落實「隱私即設計」，資料蒐集與使用不得逾越必要範圍 |
| 資訊安全 | 系統須具備足夠的防禦能力，抵禦資安攻擊與資料外洩 |
| 透明與可解釋 | 使用者有權知道自己正在與 AI 互動，高風險系統須能說明判斷依據 |
| 公平不歧視 | 避免演算法複製或放大既有的社會不平等 |
| 問責機制 | 明確劃分責任歸屬，並建立補償或保險等救濟制度 |

台灣 AI 基本法同時鼓勵資料開放共享、產業發展與人才培育（如建置監理沙盒供企業在可控範圍內測試新應用），顯示治理與創新並非互斥——而是希望在確保安全與倫理的前提下，加速產業發展。

### 五、AI 風險管理的基本流程

不論法規如何演變，企業導入 AI 時都可以用一個通用的風險管理循環來檢視自己：

1. **識別（Identify）**：這個 AI 應用可能觸及哪些風險面向（安全／隱私／偏誤／法規）？
2. **評估（Assess）**：每個風險的發生機率與影響程度各是多少？
3. **緩解（Mitigate）**：針對高優先級風險，有哪些技術或流程可以降低風險？
4. **監控（Monitor）**：上線後如何持續追蹤，確保風險沒有隨資料或環境改變而惡化？

這個循環正是 Part 3 工作坊要實際操作一次的內容。

## Part 2｜Vibe Coding 實作演練：偏誤稽核與隱私保護體驗

延續上週「Vibe Coding」的操作方式：把題目定義清楚，讓 AI 協助寫出程式碼，重點在於體驗風險與偏誤是可以被量化、被檢測的，而不是只能憑印象討論。以下兩個範例都可以在 Google Colab 直接執行。

### 範例 ①　演算法偏誤稽核：重現 COMPAS 案例的種族差異

**題目定義**：用 ProPublica 公開的 COMPAS 真實資料集，計算不同種族被告的「假陽性率」（實際未再犯、卻被系統評為高風險的比例），重現「黑人被告被誤判為高風險的比例顯著高於白人被告」這個真實發現。

**資料來源（真實公開資料，可直接下載）：**
<https://raw.githubusercontent.com/propublica/compas-analysis/master/compas-scores-two-years.csv>

**給 AI 的提示詞：**
```
請用 Python 幫我做以下事情：
1. 讀取這個網址的 CSV 資料：
   https://raw.githubusercontent.com/propublica/compas-analysis/master/compas-scores-two-years.csv
2. 只保留 race 欄位為 "African-American" 或 "Caucasian" 的資料列
3. 將 score_text 欄位中 "High" 或 "Medium" 視為系統判定「高風險」，"Low" 視為「低風險」
4. 用 two_year_recid 欄位（1=兩年內再犯，0=未再犯）作為實際結果
5. 分別計算兩個種族群體的「假陽性率」：實際未再犯（two_year_recid=0），
   卻被系統判定為高風險的比例
6. 印出兩個群體的假陽性率，並比較差異
請給我可以在 Google Colab 直接執行的完整程式碼。
```

**預期產出的程式碼骨架：**
```python
import pandas as pd

url = "https://raw.githubusercontent.com/propublica/compas-analysis/master/compas-scores-two-years.csv"
df = pd.read_csv(url)

df = df[df["race"].isin(["African-American", "Caucasian"])]
df["predicted_high_risk"] = df["score_text"].isin(["High", "Medium"])

def false_positive_rate(group):
    actual_negative = group[group["two_year_recid"] == 0]
    if len(actual_negative) == 0:
        return None
    return (actual_negative["predicted_high_risk"].sum() / len(actual_negative)) * 100

for race, group in df.groupby("race"):
    fpr = false_positive_rate(group)
    print(f"{race} 的假陽性率：{fpr:.1f}%")
```

**延伸練習**：把 race 換成 sex 欄位，看看性別之間是否也存在類似的差異；或改用 decile_score（1-10 分的風險分數）畫出兩個種族群體的分數分布直方圖，比較整體分布是否一致。

**管理意涵**：假陽性率的落差正是 ProPublica 當年報導的核心發現——即使模型沒有直接使用種族欄位，資料中的隱含關聯仍可能導致系統性的不公平結果。這也是台灣 AI 基本法「公平不歧視」原則要求企業在導入 AI 決策系統前，必須做的稽核類型。

### 範例 ②　去識別化與再識別風險體驗

**題目定義**：用一組模擬的客戶資料，體驗「單純移除姓名、身分證字號」是否真的能保護隱私，以及如何透過欄位「概化（generalization）」降低再識別風險。

**給 AI 的提示詞：**
```
請用 Python 幫我做以下事情：
1. 建立一個模擬的客戶資料表，欄位包含：姓名、身分證字號、出生年月日、
   性別、5位數郵遞區號、年收入、疾病史（至少 10 筆資料，資料可自行捏造）
2. 示範「單純去識別化」：移除姓名與身分證字號兩個欄位
3. 說明並示範：如果外部有一份「性別＋出生年月日＋郵遞區號」的公開名冊
   （例如選民名冊），為什麼光靠這三個欄位就有機會比對回真實身份
4. 示範「概化」處理：把出生年月日改成「出生年」，
   把 5 位數郵遞區號改成前 3 碼（區域層級），降低唯一識別的機率
5. 比較概化前後，每一筆資料在資料表中還有多少筆「一模一樣」的紀錄
   （這個數字越大，代表越不容易被單獨識別出來，也就是 k-anonymity 的概念）
請給我可以在 Google Colab 直接執行的完整程式碼。
```

**預期產出的程式碼骨架：**
```python
import pandas as pd

data = pd.DataFrame({
    "姓名": ["王小明", "陳小華", "李大同", "張美玲", "林志豪"],
    "身分證字號": ["A123456789", "B223456789", "C323456789", "D423456789", "E523456789"],
    "出生年月日": ["1985-03-12", "1990-07-21", "1985-11-05", "1978-02-14", "1990-07-30"],
    "性別": ["M", "F", "M", "F", "M"],
    "郵遞區號": ["10041", "40045", "10043", "80041", "40049"],
    "年收入": [850000, 620000, 900000, 550000, 700000],
})

# 步驟一：單純去識別化
deidentified = data.drop(columns=["姓名", "身分證字號"])
print("單純去識別化後：")
print(deidentified)

# 步驟二：概化處理
generalized = deidentified.copy()
generalized["出生年"] = pd.to_datetime(generalized["出生年月日"]).dt.year
generalized["郵遞區號前3碼"] = generalized["郵遞區號"].str[:3]
generalized = generalized.drop(columns=["出生年月日", "郵遞區號"])
print("\n概化處理後：")
print(generalized)

# 步驟三：檢查每組準識別欄位組合出現的筆數（k值）
k_check = generalized.groupby(["性別", "出生年", "郵遞區號前3碼"]).size()
print("\n各組合出現筆數（k值，越小代表越容易被單獨識別）：")
print(k_check)
```

**延伸練習**：試著調整郵遞區號的概化程度（例如改成只取前 2 碼），觀察 k 值如何變化；並思考——概化程度越高，隱私保護越好，但資料分析的精確度會不會因此下降？這中間的取捨要怎麼決定？

**管理意涵**：這個練習說明「移除姓名」不等於「無法識別個人」。性別、出生年月日、郵遞區號這類「準識別欄位」的組合，往往才是真正的隱私風險來源，這正是台灣 AI 基本法「隱私即設計」理念要處理的核心問題。
