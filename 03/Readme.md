## Part 1｜主題課程：機器學習的分類與處理流程

### 一、機器學習的四種學習方式

傳統上，要讓電腦辨識出一張照片裡有沒有貓，需要把所有貓的特徵和條件一條一條列出來，非常繁瑣。機器學習改變了這個做法——讓電腦透過大量資料自己「學」出規律，就像小孩透過觀察與回饋學會認貓一樣。機器學習依照學習方式的不同，可以分成四大類：

| 學習方式 | 核心邏輯 | 商業應用例子 |
|---|---|---|
| **監督式學習（Supervised Learning）** | 用已標註答案的資料訓練模型，讓模型學會輸入與輸出之間的關係 | 分類（Classification）：判斷客戶會不會流失、郵件是不是垃圾信；迴歸（Regression）：預測房價、股價、下個月營收 |
| **非監督式學習（Unsupervised Learning）** | 資料沒有標註答案，目標是從資料中自己找出結構與規律 | 分群（Clustering）：把客戶依消費行為分成不同族群，作為行銷區隔的依據 |
| **半監督式學習（Semi-supervised Learning）** | 只有少量資料有標註，大量資料沒有標註，兩者一起訓練 | 內容分類（只有少數文章被標記類別）、影像辨識（只有少數照片有標籤）、網路入侵偵測（入侵樣本稀少） |
| **強化學習（Reinforcement Learning）** | 代理人（Agent）在環境中不斷嘗試，依照回饋（獎勵或懲罰）學習最佳策略，而不是靠標註資料 | AlphaGo 透過分析大量棋譜、不斷自我對弈學習策略，最終擊敗世界圍棋冠軍；也常見於自動駕駛、機器人控制、動態定價 |

**監督式學習再細分**：分類（Classification）處理的是「屬於哪一類」的問題（會不會流失、是貓還是狗）；迴歸（Regression）處理的是「數值是多少」的問題（房價、溫度、股價）。這兩者的差異，會直接影響後面第 4、5 週要選用的演算法。

### 二、機器學習六步驟流程

不管解決什麼商業問題，機器學習專案大致都會經歷六個關鍵步驟，形成一個可以反覆迭代的循環：

| 步驟 | 內容 | 商業對應的工作 |
|---|---|---|
| **① 收集數據** | 蒐集與問題相關的結構化資料（表格）或非結構化資料（影像、文字、音訊），確保資料準確、完整、無明顯偏差 | 這筆資料公司內部有沒有？分散在哪些系統（CRM、ERP、感測器）？需不需要跨部門調閱？ |
| **② 數據前處理** | 資料清理（處理重複、缺失、異常值）、特徵工程（選擇並轉換有意義的特徵）、標準化（讓不同尺度的特徵可以公平比較） | 這一步通常最花時間，也最考驗對業務的理解——哪些欄位才是真正有意義的預測因子？ |
| **③ 選擇模型** | 依問題性質（分類／迴歸／分群／強化學習）與資料特性，選擇適合的演算法，同時考量複雜度、效能與可解釋性的取捨 | 金融、醫療等需要對客戶或主管機關解釋決策依據的場景，往往會優先選擇可解釋性較高的模型 |
| **④ 訓練模型** | 用前處理完的資料訓練模型，讓模型反覆調整參數以擬合資料規律；通常會把資料切成訓練集與驗證集 | 需要投入運算資源與時間，也是「過擬合／欠擬合」問題會出現的階段（見下方說明） |
| **⑤ 評估模型** | 用沒有參與訓練的測試資料，檢驗模型的整體表現 | 見下方「常見評估指標」說明 |
| **⑥ 部署** | 把訓練好的模型整合進實際的軟體、設備或服務中上線運作 | 需要同時考慮可擴展性、效能、資安與後續維護——模型上線後還要持續監控，資料分布改變時模型表現可能會變差 |

**過擬合（Overfitting）與欠擬合（Underfitting）**：如果模型在訓練集上表現極佳，但在驗證集或新資料上表現明顯下降，代表模型「死記」了訓練資料的細節，卻學不會可以泛化到新資料的規律，這叫做過擬合；相反地，如果模型在訓練集與驗證集上的表現都不理想，代表模型太簡化，沒有學到資料中的關鍵模式，這叫做欠擬合。管理上可以把過擬合想成「死背考古題、但換一種問法就不會了」，欠擬合則是「連考古題都讀不熟」。

**常見評估指標：**

| 指標 | 定義 | 什麼時候特別重要 |
|---|---|---|
| 準確率（Accuracy） | AI 判斷正確的整體比例 | 資料中正負樣本比例接近均衡時較適用 |
| 精確率（Precision） | AI 判定為「正向」的結果中，實際上真的是正向的比例 | 誤判成本高的場景（例如誤判優質客戶為高風險而拒絕往來） |
| 召回率（Recall） | 所有實際為正向的案例中，有多少被 AI 成功找出 | 漏抓成本高的場景（例如漏抓真正會違約的客戶、漏抓真正故障的設備） |
| F1 分數（F1-score） | 同時綜合考量精確率與召回率的整體表現 | 精確率與召回率同樣重要、需要一個綜合指標時 |

由於單一指標往往無法完整呈現模型的實際效能，實務上必須依應用情境搭配多種指標一起看——這也是下週要深入討論的「決策門檻權衡」的基礎。

### 三、商業問題轉譯：從模糊的痛點到可解的機器學習題目

多數經理人提出的痛點都是模糊的——「我們想減少客戶流失」「我們想降低設備故障率」。要讓資料團隊真正動手，必須先把這句話轉譯成一個具體、可執行的機器學習題目。可以用以下四個問題自我檢查：

1. **我們到底想預測╱判斷什麼？**（定義目標變數 Target Variable）
2. **這是分類問題還是迴歸問題？**（會不會流失是分類；剩餘壽命是幾天是迴歸）
3. **需要哪些特徵（Features）？這些資料公司內部有沒有、存放在哪裡？**
4. **如果現在沒有這個模型，企業目前是怎麼做決策的？換成模型之後，決策的節點會在哪裡改變？**

**轉譯範例一｜客戶流失**

| 轉譯步驟 | 內容 |
|---|---|
| 模糊痛點 | 「我們想知道哪些客戶快要流失，好提前挽留」 |
| 目標變數 | 客戶在未來 30 天內是否會流失（是／否） |
| 問題類型 | 分類問題 |
| 可能的特徵 | 使用年資、合約類型、月費金額、近期客服申訴次數、使用量變化趨勢 |
| 資料來源 | CRM 系統的客戶基本資料、帳務系統的繳費紀錄、客服系統的申訴紀錄 |
| 決策節點的改變 | 從「客戶主動打來取消才知道」，變成「系統每週產出高風險名單，客服主動聯繫」 |

**轉譯範例二｜設備故障**

| 轉譯步驟 | 內容 |
|---|---|
| 模糊痛點 | 「我們想在設備故障前就先發現異常」 |
| 目標變數 | 設備在未來 7 天內是否會故障（是／否），或設備的剩餘壽命還有幾天 |
| 問題類型 | 前者是分類問題，後者是迴歸問題 |
| 可能的特徵 | 感測器讀數（溫度、震動、電流）、上次維護距今天數、累積運轉時數 |
| 資料來源 | 設備上的 IoT 感測器、維修保養紀錄系統 |
| 決策節點的改變 | 從「定期巡檢或壞了才修」，變成「系統提前預警，安排計畫性停機維護」 |

這個轉譯框架，正是本週實作要練習的核心技能，也是接下來期中、期末報告「AI 導入方案設計」段落一定會用到的思考方式。

## Part 2｜Vibe Coding 實作演練：從商業問題到六步驟流程

### 範例 ①　用 AI 檢查自己的商業問題轉譯是否夠具體

**題目定義**：練習把自己企業的一個模糊痛點，套用上方四個問題的框架，並請 AI 幫忙檢查轉譯是否夠具體、有沒有遺漏的環節。這個練習不需要寫程式，重點是把問題定義清楚。

**給 AI 的提示詞（把方括號內容換成你自己的情境）：**
```
我是一名 [你的產業別] 的經理人，我們公司目前遇到的痛點是：
[描述你的模糊痛點，例如「業務接單常常延誤交期」]

請幫我用以下框架，把這個痛點轉譯成一個機器學習可以處理的具體題目：
1. 目標變數是什麼？（我們要預測或判斷的結果）
2. 這是分類問題還是迴歸問題？
3. 可能需要哪些特徵？這些資料我們公司內部通常會存放在哪個系統？
4. 如果沒有這個模型，我們現在是怎麼做決策的？導入模型後，決策節點會在哪裡改變？
如果我提供的資訊不足以完成轉譯，請直接反問我需要補充什麼。
```

**延伸練習**：把 AI 反問你的問題，當作下週要準備的功課——這些通常正是資料蒐集階段最容易卡關的地方。

### 範例 ②　完整跑一次六步驟流程：客戶流失預測

**題目定義**：用真實的電信客戶資料，完整走一次「收集數據 → 前處理 → 選模型 → 訓練 → 評估 → （模擬）部署」六步驟，並親眼看到「過擬合」實際發生時是什麼樣子。

**資料來源（真實公開資料，IBM 電信客戶流失資料集，可直接下載）：**
<https://raw.githubusercontent.com/IBM/telco-customer-churn-on-icp4d/master/data/Telco-Customer-Churn.csv>

**給 AI 的提示詞：**
```
請用 Python 幫我完整跑一次機器學習六步驟流程，處理「客戶流失預測」問題：
1. 讀取這個網址的 CSV 資料：
   https://raw.githubusercontent.com/IBM/telco-customer-churn-on-icp4d/master/data/Telco-Customer-Churn.csv
2. 數據前處理：處理 TotalCharges 欄位裡的空白值，把類別型欄位轉換成模型看得懂的數值格式，
   把 Churn 欄位轉成 0/1
3. 切分訓練集與測試集
4. 分別訓練兩個模型：
   (a) 一個簡單的決策樹（限制樹的深度，例如 max_depth=3）
   (b) 一個複雜的決策樹（不限制深度）
5. 分別印出這兩個模型在「訓練集」與「測試集」上的準確率，
   讓我可以比較哪一個模型出現了過擬合的現象
6. 針對表現較好的模型，印出精確率、召回率、F1 分數
請給我可以在 Google Colab 直接執行的完整程式碼。
```

**預期產出的程式碼骨架：**
```python
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import accuracy_score, precision_score, recall_score, f1_score
from sklearn.preprocessing import LabelEncoder

url = "https://raw.githubusercontent.com/IBM/telco-customer-churn-on-icp4d/master/data/Telco-Customer-Churn.csv"
df = pd.read_csv(url)

# 數據前處理
df["TotalCharges"] = pd.to_numeric(df["TotalCharges"], errors="coerce")
df["TotalCharges"] = df["TotalCharges"].fillna(df["TotalCharges"].median())
df["Churn"] = df["Churn"].map({"Yes": 1, "No": 0})

X = df.drop(columns=["customerID", "Churn"])
X = X.apply(LabelEncoder().fit_transform)  # 簡化示範：類別欄位直接編碼
y = df["Churn"]

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42
)

# 簡單模型 vs 複雜模型
simple_model = DecisionTreeClassifier(max_depth=3, random_state=42)
complex_model = DecisionTreeClassifier(max_depth=None, random_state=42)

for name, model in [("簡單模型（限制深度）", simple_model), ("複雜模型（不限深度）", complex_model)]:
    model.fit(X_train, y_train)
    train_acc = accuracy_score(y_train, model.predict(X_train))
    test_acc = accuracy_score(y_test, model.predict(X_test))
    print(f"{name}：訓練集準確率 {train_acc:.3f}，測試集準確率 {test_acc:.3f}")

# 針對複雜模型印出更完整的指標
y_pred = complex_model.predict(X_test)
print("精確率：", precision_score(y_test, y_pred))
print("召回率：", recall_score(y_test, y_pred))
print("F1 分數：", f1_score(y_test, y_pred))
```

**延伸練習**：觀察複雜模型是不是「訓練集準確率接近 100%，但測試集準確率明顯下降」——這就是過擬合的典型徵兆。試著調整 `max_depth` 的數值（例如 5、10、20），看看訓練集與測試集的準確率差距如何變化。

**管理意涵**：這個練習具體呈現了「模型越複雜不代表越好用」——選模型時，可解釋性、穩定性、泛化能力，往往比訓練集上的漂亮數字更重要，這也是本週商業問題轉譯之後，下週要接續討論「決策門檻」與商業代價的基礎。
