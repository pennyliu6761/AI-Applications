## Part 1｜主題課程：分類演算法、類別不平衡與決策門檻

### 一、分類演算法概覽：決策樹與 KNN

監督式學習中的分類演算法，大致可分成三類邏輯：邏輯規則式（決策樹、隨機森林）、統計學習式（貝氏分類器、SVM）、實例比對式（KNN）。本週聚焦最常用、也最容易向管理層解釋的兩種：

**決策樹（Decision Tree）**：核心概念是透過一系列的問題，逐步推斷最終答案，就像模仿人類思考決策的過程——例如判斷一隻動物是鳥、狗、蝦還是魚，就是不斷問「有沒有殼？」「有沒有腳？」逐層篩選。商業上的典型應用是銀行信貸審核：用客戶的收入、信用歷史、債務水準等歷史資料，訓練一個模型自動判斷「這筆貸款該不該批准」。決策樹的最大優勢是**直觀、可解釋**——這在金融、醫療等需要向客戶或主管機關說明判斷依據的場景中特別重要。隨機森林（Random Forest）則是同時訓練多棵決策樹並綜合投票，能處理更複雜的分類任務，但可解釋性會隨之下降。

**K-近鄰演算法（KNN）**：核心概念是「物以類聚」——當出現一筆新資料時，不需要建立複雜的數學模型，而是直接觀察它在特徵空間中距離最近的 K 個鄰居，用多數決來判斷類別。商業上最典型的應用是電商推薦：平台比較某位使用者與其他使用者在購買、瀏覽行為上的相似度，找出「最相近的一群人」，再推薦這群人喜歡的商品。

### 二、類別不平衡問題（Imbalanced Data）

教科書用兩個真實資料集清楚呈現了這個問題：

| 案例 | 資料分布 | 模型表現 |
|---|---|---|
| 電信客戶流失預測 | 測試集中 148 位未流失客戶（類別 0）、僅 32 位流失客戶（類別 1） | 對類別 0：精確率 0.90、召回率 0.94，表現穩定；對類別 1：精確率僅 0.64、召回率僅 0.50，模型只找出約一半真正會流失的客戶 |
| 信用卡詐騙偵測 | 284,807 筆交易中，正常交易 284,315 筆（99.83%），詐騙交易僅 492 筆（0.17%） | 若模型無腦地把所有交易都判為「正常」，準確率也能高達 99.8%，但完全沒有偵測詐騙的能力 |

**這說明了一件事：當資料存在類別不平衡時，準確率（Accuracy）會嚴重誤導管理判斷。** 模型很容易傾向預測為多數類別，因為這樣「整體錯得最少」，但企業真正在意的往往是那個發生機率很低、卻代價很高的少數類別（流失客戶、詐騙交易、故障設備）。因此在類別不平衡的場景下，必須改看精確率、召回率、F1 分數，甚至下方要談的混淆矩陣與決策門檻。

**常見的因應方法：**
- **過採樣（Over-sampling）**：增加少數類別的樣本數量（例如用 SMOTE 演算法合成新的少數類別樣本）
- **欠採樣（Under-sampling）**：減少多數類別的樣本數量，讓兩類比例接近
- **類別權重（Class Weight）**：訓練時讓模型對少數類別的誤判給予更高的懲罰權重，不需要改變原始資料

### 三、混淆矩陣與商業代價：漏報 vs. 誤報

要理解分類模型的商業價值，必須先看懂混淆矩陣（Confusion Matrix）——它把模型的預測結果拆成四種情況：

| | 實際為正向（例如：真的詐騙） | 實際為負向（例如：真的正常） |
|---|---|---|
| **模型判定為正向** | 真陽性 TP（抓對了） | **假陽性 FP（誤報）**——把正常的判成異常 |
| **模型判定為負向** | **假陰性 FN（漏報）**——把異常的判成正常 | 真陰性 TN（判對了） |

**漏報（FN）與誤報（FP）的商業代價，在不同場景下完全不對等：**

| 應用場景 | 誤報（FP）的代價 | 漏報（FN）的代價 |
|---|---|---|
| 信用卡詐騙偵測 | 正常交易被誤擋，客戶當下無法刷卡，體驗變差，嚴重時可能導致客戶流失 | 詐騙交易沒被抓到，銀行或客戶直接承受金錢損失 |
| 不良品檢測 | 良品被誤判為瑕疵品，導致報廢或重工，增加不必要的生產成本 | 瑕疵品流入市場，引發客訴、退貨，甚至召回，商譽受損 |
| 客戶流失預警 | 誤判即將流失的忠誠客戶，白白發送不必要的挽留優惠，侵蝕利潤 | 真正要流失的客戶沒被抓到，錯失挽留機會，直接損失該客戶終身價值 |

管理者的任務，就是先把這兩種錯誤各自的「單位成本」估出來，才能決定模型該往哪個方向調整。

### 四、決策門檻權衡（Decision Threshold）

多數分類模型輸出的不是「是」或「否」，而是一個 0 到 1 之間的機率（例如「這筆交易有 73% 的機率是詐騙」）。企業必須自己設定一個**門檻（threshold）**，超過這個機率就判定為正向，這個門檻預設通常是 0.5，但 0.5 不一定是對企業最有利的選擇：

- **調低門檻**（例如從 0.5 降到 0.3）：模型會更容易把交易判定為「可疑」，**召回率上升**（漏抓的詐騙變少），但**精確率下降**（更多正常交易被誤擋，誤報增加）。
- **調高門檻**（例如從 0.5 升到 0.7）：模型會更保守地判定「可疑」，**精確率上升**（比較少冤枉正常交易），但**召回率下降**（更多詐騙沒被抓到，漏報增加）。

**這是一個沒有標準答案的商業決策，取決於誤報與漏報各自的成本結構。** 如果漏報一筆詐騙的平均損失是誤報一筆交易的成本的 10 倍，理性的做法就是把門檻調低，寧可多攔一些正常交易，也要盡量抓出詐騙。這種「用預期總成本找出最適門檻」的分析方式，就是本週實作要動手做一次的「停損決策分析」。

**計算邏輯：**

```
預期總成本 = (誤報筆數 × 每筆誤報的成本) + (漏報筆數 × 每筆漏報的成本)
```

在不同門檻下分別算出這個總成本，找出讓總成本最小的門檻，就是資料驅動的決策依據，而不是憑感覺選 0.5。

## Part 2｜Vibe Coding 實作演練：信用卡詐騙偵測與決策門檻分析

### 範例 ①　建立信用卡詐騙分類模型，看見類別不平衡的真實影響

**題目定義**：用教科書採用的真實信用卡詐騙資料集，訓練一個分類模型，並具體比較「不處理類別不平衡」與「設定類別權重」兩種做法，對少數類別（詐騙）辨識能力的影響。

**資料來源（與教科書相同的真實資料集，透過 OpenML 直接下載，不需要 Kaggle 帳號）：**
這是 ULB（布魯塞爾自由大學）機器學習研究小組公開的信用卡詐騙資料集，收錄 2013 年 9 月歐洲持卡人兩天內的 284,807 筆交易，492 筆為詐騙（占 0.17%）。

**給 AI 的提示詞：**
```
請用 Python 幫我做以下事情：
1. 用 sklearn.datasets.fetch_openml(data_id=1597, as_frame=True) 讀取信用卡詐騙資料集
2. 印出 Class 欄位（1=詐騙，0=正常）的筆數與比例，確認類別不平衡的程度
3. 切分訓練集與測試集（測試集占 30%）
4. 分別訓練兩個羅吉斯迴歸模型：
   (a) 不做任何處理的一般模型
   (b) 設定 class_weight="balanced" 的模型
5. 針對這兩個模型，分別印出混淆矩陣、精確率、召回率、F1 分數，
   讓我可以比較兩者在「抓出詐騙」這件事上的差異
請給我可以在 Google Colab 直接執行的完整程式碼。
```

**預期產出的程式碼骨架：**
```python
from sklearn.datasets import fetch_openml
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import confusion_matrix, precision_score, recall_score, f1_score

data = fetch_openml(data_id=1597, as_frame=True)
df = data.frame
df["Class"] = df["Class"].astype(int)

print(df["Class"].value_counts())
print(df["Class"].value_counts(normalize=True))

X = df.drop(columns=["Class"])
y = df["Class"]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42, stratify=y
)

for name, weight in [("一般模型", None), ("類別權重平衡模型", "balanced")]:
    model = LogisticRegression(max_iter=1000, class_weight=weight)
    model.fit(X_train, y_train)
    y_pred = model.predict(X_test)
    print(f"\n=== {name} ===")
    print("混淆矩陣：\n", confusion_matrix(y_test, y_pred))
    print("精確率：", precision_score(y_test, y_pred))
    print("召回率：", recall_score(y_test, y_pred))
    print("F1 分數：", f1_score(y_test, y_pred))
```

**延伸練習**：觀察「一般模型」是不是精確率很高但召回率偏低（很保守，不太敢判定為詐騙）；而「類別權重平衡模型」召回率是否明顯提升，但精確率是否隨之下降。這正是上方談到的漏報／誤報權衡。

### 範例 ②　決策門檻與停損決策分析

**題目定義**：假設銀行風控部門估算出「每筆誤報（正常交易被擋下）」平均會造成客戶抱怨與客服處理成本約新台幣 150 元；「每筆漏報（詐騙未被抓到）」平均損失約新台幣 8,000 元。請用模型輸出的機率值，測試不同決策門檻下的預期總成本，找出成本最低的門檻。

**給 AI 的提示詞：**
```
接續上一題訓練好的類別權重平衡模型，請幫我做以下事情：
1. 取得模型對測試集輸出的詐騙機率（predict_proba）
2. 測試從 0.1 到 0.9、間隔 0.1 的九個門檻值
3. 針對每一個門檻，計算：
   - 在這個門檻下的混淆矩陣（誤報數、漏報數）
   - 預期總成本 = 誤報數 × 150 + 漏報數 × 8000
4. 把每個門檻對應的總成本畫成折線圖，並印出總成本最低的門檻是多少
請給我可以在 Google Colab 直接執行的完整程式碼。
```

**預期產出的程式碼骨架：**
```python
import numpy as np
import matplotlib.pyplot as plt

y_prob = model.predict_proba(X_test)[:, 1]

cost_fp = 150      # 每筆誤報的成本
cost_fn = 8000     # 每筆漏報的成本
thresholds = np.arange(0.1, 1.0, 0.1)
total_costs = []

for t in thresholds:
    y_pred_t = (y_prob >= t).astype(int)
    cm = confusion_matrix(y_test, y_pred_t)
    tn, fp, fn, tp = cm.ravel()
    total_cost = fp * cost_fp + fn * cost_fn
    total_costs.append(total_cost)
    print(f"門檻 {t:.1f}：誤報 {fp} 筆，漏報 {fn} 筆，預期總成本 {total_cost:,} 元")

best_threshold = thresholds[np.argmin(total_costs)]
print(f"\n總成本最低的門檻為：{best_threshold:.1f}")

plt.plot(thresholds, total_costs, marker="o")
plt.xlabel("決策門檻")
plt.ylabel("預期總成本（元）")
plt.title("不同決策門檻下的預期總成本")
plt.show()
```

**延伸練習**：把誤報成本改成 1,500 元（例如客戶因此轉往競爭對手，流失整個客戶關係），重新跑一次，觀察最適門檻會不會往上移動。體會「成本結構一旦改變，最適決策也會跟著改變」。

**管理意涵**：這個練習把「該把門檻設在哪裡」從一個憑印象或工程師預設值的決定，變成一個有數字支撐的管理決策——這正是本課程期望各位在面對資料科學團隊提出的模型時，能夠主動提出的關鍵問題：「你們的門檻是怎麼定的？漏報跟誤報的成本，誰幫忙估過？」
