## Part 1｜主題課程：神經網路如何學習，以及黑盒子問題

### 一、神經元如何模擬人腦

人類大腦約由 850 至 1200 億個神經元組成，透過「接收資訊 → 分析判斷 → 產生輸出」的流程進行學習與決策。類神經網路（Artificial Neural Network）模擬的正是這個邏輯：

- 每個神經元接收多個輸入值（x1, x2, …, xn）
- 每個輸入都對應一個**權重（weight）**，代表這個輸入的重要程度——權重越大，代表這個特徵對輸出的影響越大
- 加權加總後，通常還會加上一個**偏差項（bias）**，讓決策邊界不必被迫通過原點，大幅提升模型的分類彈性
- 最後透過**啟動函數（activation function，如 Sigmoid、ReLU）**引入非線性，讓模型能處理比「一條直線」複雜得多的分類問題

**當神經網路的輸出與正確答案不一致時**，系統會透過反向傳播機制調整權重，讓下一次預測更接近正確答案——這個過程就像人類從錯誤中學習，隨著訓練資料與訓練次數增加，模型逐漸累積出穩定的判斷能力。

### 二、特徵學習：深度學習與傳統方法的根本差異

在傳統機器學習中，「特徵」通常需要由人工設計與挑選（例如工程師自己決定「用收入、年齡、負債比來判斷違約」）；但在深度學習架構中，模型具備**自動學習特徵**的能力，這個過程稱為「特徵學習（Feature Learning）」。

以人臉辨識為例：神經網路不需要工程師明確告訴它「要看眼睛形狀、鼻子輪廓」，而是透過大量資料訓練，自動辨識出哪些視覺特徵對區分不同人物最具代表性。透過多層神經網路的堆疊，模型能從低階特徵（邊緣、紋理）逐層建構出高階抽象特徵（形狀、語意），這正是「深度」學習這個名稱的由來。

**管理意涵**：這代表深度學習特別適合「連工程師自己都說不清楚該看哪些特徵」的問題（例如瑕疵品的細微紋路、顧客語氣中的不滿），但也正因為特徵是模型自己找出來的，才衍生出下面要談的「黑盒子」問題。

### 三、黑盒子問題與可解釋性管理瓶頸

深度模型內部結構複雜，往往難以說明「為什麼做出這個判斷」——這被稱為「黑盒子模型」。當模型只有一兩層、參數不多時，還能大致回溯每個特徵的權重；但當模型有數十層、數百萬個參數時，即使是開發者自己，也很難具體說明「為什麼這張圖被判定為瑕疵品」「為什麼這位客戶被評為高風險」。

這在管理上會造成幾個實際的瓶頸：

| 情境 | 黑盒子帶來的問題 |
|---|---|
| 醫療診斷 | 若模型誤判，醫師難以判斷是模型邏輯錯誤還是資料異常，責任歸屬不清 |
| 金融信用評分 | 若客戶被拒絕貸款，金融機構可能面臨「無法具體說明拒絕理由」的法遵風險（呼應第 2 週 AI 基本法「透明與可解釋」原則） |
| 工廠品管 | 若模型把良品判為瑕疵品，產線人員不容易知道該從哪個環節調整製程 |

**因應做法**：企業導入深度學習時，通常會搭配「可解釋 AI（Explainable AI, XAI）」工具（例如熱力圖，標示模型在圖片中「看」的是哪個區域），或是在高風險決策環節保留人工複核，而不是把黑盒子模型的輸出直接當成最終決策。

## Part 2｜Vibe Coding 實作演練：訓練一個簡單的神經網路，觀察黑盒子現象

### 範例①　從零訓練一個小型神經網路，體驗權重與決策邊界

**題目定義**：用一組簡單的二維資料，訓練一個只有一層隱藏層的神經網路，實際「看見」權重調整的過程，以及加入偏差項前後，決策邊界如何改變。

**給 AI 的提示詞：**
```
請用 Python 幫我做以下事情：
1. 用 sklearn.datasets.make_moons 產生一組簡單的二維二分類資料（月牙形，不是線性可分）
2. 用 sklearn 的 MLPClassifier（一個只有 4 個神經元的隱藏層）訓練分類模型
3. 畫出資料點的散佈圖，並疊加模型的決策邊界（decision boundary）
4. 接著訓練一個「沒有隱藏層」的簡單邏輯迴歸模型，同樣畫出決策邊界，
   讓我比較兩者的差異
請給我可以在 Google Colab 直接執行的完整程式碼。
```

**預期產出的程式碼骨架：**
```python
import numpy as np
import matplotlib.pyplot as plt
from sklearn.datasets import make_moons
from sklearn.neural_network import MLPClassifier
from sklearn.linear_model import LogisticRegression

X, y = make_moons(n_samples=300, noise=0.2, random_state=42)

def plot_boundary(model, X, y, title):
    xx, yy = np.meshgrid(np.linspace(X[:,0].min()-0.5, X[:,0].max()+0.5, 300),
                          np.linspace(X[:,1].min()-0.5, X[:,1].max()+0.5, 300))
    Z = model.predict(np.c_[xx.ravel(), yy.ravel()]).reshape(xx.shape)
    plt.contourf(xx, yy, Z, alpha=0.3)
    plt.scatter(X[:,0], X[:,1], c=y, edgecolors="k")
    plt.title(title)
    plt.show()

nn_model = MLPClassifier(hidden_layer_sizes=(4,), max_iter=2000, random_state=42)
nn_model.fit(X, y)
plot_boundary(nn_model, X, y, "神經網路（4 個神經元）的決策邊界")

linear_model = LogisticRegression()
linear_model.fit(X, y)
plot_boundary(linear_model, X, y, "邏輯迴歸（無隱藏層）的決策邊界")
```

**延伸練習**：把隱藏層神經元數量從 4 個改成 1 個，觀察決策邊界會退化成什麼樣子；再改成 20 個，觀察邊界是否變得過度曲折（這其實就是上週提過的過擬合現象，在神經網路上的呈現）。

**管理意涵**：邏輯迴歸的決策邊界永遠是一條直線（或平面），而神經網路能彎曲、能貼合資料的複雜形狀——這正是深度學習能處理複雜問題的原因，但曲折的邊界也代表模型的判斷邏輯，遠比一條直線的方程式難以向人解釋。

### 範例②　智慧檢驗 ROI 試算：傳統抽檢 vs. AI 全檢

**題目定義**：用一組假設情境，比較「人工抽檢」與「AI 全檢」兩種品管方式的成本與效益，計算投資回收期。

**給 AI 的提示詞：**
```
請用 Python 幫我做一個簡單的 ROI 試算：
情境：某工廠每月生產 100,000 件產品，瑕疵率約 2%。
- 人工抽檢：只抽驗 10% 的產品，抽驗到的瑕疵品可攔截，
  但未抽驗到的瑕疵品有 70% 機率流入市場，每件流入市場的瑕疵品
  平均賠償／商譽損失為 500 元，人工抽檢每月人事成本 15 萬元。
- AI 全檢：導入一套 AI 影像檢驗系統，可檢驗 100% 產品，
  攔截率提升到 95%，系統建置成本 300 萬元（一次性），
  每月維運成本 5 萬元。
請計算兩種方案在第 1 年、第 2 年的總成本（含瑕疵品流入市場的損失），
並算出 AI 方案大約在第幾個月可以打平建置成本（回本期）。
```

**延伸練習**：把 AI 系統的攔截率從 95% 調降到 85%，或把瑕疵率從 2% 調成 0.5%，重新計算回本期，觀察哪個變數對投資決策的影響最大。

**管理意涵**：ROI 試算不是要證明「AI 一定划算」，而是提供一個結構化的方式，讓管理者看清楚在什麼樣的瑕疵率、什麼樣的損失規模下，導入 AI 才是理性的選擇——這正是本課程一貫強調的「先想清楚，再動手做」的態度。

### 教師示範精讀：一篇「雙層架構」論文怎麼拆解

這篇論文的架構比較特別——它不是只用一個模型解決問題，而是設計了**兩層、各自獨立運作的模型**，很適合練習「拆解一個複合式研究設計」。

**① 研究問題**：工廠設備故障預測面臨兩個現實困境：真正的故障事件很稀少（沒有大量標註好的「故障」資料可以訓練監督式模型），但企業又需要能提早示警的機制。

**② 第一層——LSTM 自編碼器做異常偵測（非監督式）**：作者只用「正常運轉」的振動訊號訓練一個 LSTM 自編碼器（Autoencoder），模型的任務是學會「重建」正常訊號。當新的訊號進來時，如果模型重建得很差（重建誤差大），就代表這筆訊號「看起來不像正常運轉」，可能是異常前兆。門檻的定義方式是統計式的：**τ = μ + 3σ**（用驗證集重建誤差的平均值加三倍標準差），而不是憑感覺設定，這是非監督式異常偵測的標準做法。

**③ 第二層——MLP 做故障分類（監督式）**：另外用六個操作參數（震動、溫度、壓力、馬達轉速、扭力、濕度）訓練一個簡單的多層感知器（MLP），直接判斷「現在是不是故障狀態」。這一層資料是不平衡的（正常 87.7% vs. 故障 12.3%），論文用精確率、召回率、F1、特異度（specificity）、MCC 等多種指標一起檢視，而不是只看準確率——這正是第 4 週學過的類別不平衡處理原則的真實應用案例。

**④ 兩層架構是「並行」而非「串接」**：值得特別注意的是，這兩個模型是各自獨立運作、分析同一批資料流，最後才在決策層把兩邊的結果合併參考，並不是「先跑自編碼器，把異常的部分才丟給 MLP」這種串接關係。這種模組化設計的好處，是兩個模型可以分開維護、更新。

**⑤ 論文誠實揭露的限制**：作者坦承 MLP 的「故障標籤」其實是用預先設定好的規則（例如震動超過某個數值）產生的，不是真實世界中人工確認過的故障事件——這代表 MLP 學到的其實是「規則的一致性」，而不是「發現規則以外的新故障模式」。這是研究設計上很誠實、也很值得學習的自我批判。

**這篇論文對我們的啟示**：當你面對「異常事件很稀少」的預測性維護問題時，「非監督式異常偵測 + 監督式分類」的雙層架構，是業界常見且務實的解法，不需要一開始就強求一個模型解決所有問題。

### Vibe Coding 簡易重現：用模擬振動訊號體驗 LSTM 自編碼器異常偵測

**題目定義**：由於論文的真實資料集需要 Kaggle 帳號下載，這裡改用模擬的振動訊號資料，重現論文最核心的邏輯——訓練一個只看過「正常訊號」的自編碼器，並用 τ = μ + 3σ 的統計門檻找出異常。

**給 AI 的提示詞：**
```
請用 Python 幫我做以下事情：
1. 模擬產生一段 3000 個時間點的振動訊號，前 2500 個點是「正常」訊號
   （用固定振幅的正弦波加上小幅隨機雜訊），後 500 個點在中間穿插幾段
   「異常」訊號（振幅明顯變大或出現突波）
2. 用滑動視窗（每 30 個時間點一組）把正常訊號切成訓練序列
3. 用 Keras 建立一個簡單的 LSTM 自編碼器（LSTM 層 + Dense 層重建輸出），
   只用正常訊號的序列訓練
4. 計算每個測試序列的重建誤差（MAE），並用正常訊號驗證集的
   「平均值 + 3倍標準差」設定異常門檻 τ
5. 標出哪些測試序列的重建誤差超過門檻，畫圖呈現原始訊號與被標記的異常區段
請給我可以在 Google Colab 直接執行的完整程式碼。
```

**預期產出的程式碼骨架：**
```python
import numpy as np
import matplotlib.pyplot as plt
from tensorflow import keras
from tensorflow.keras import layers

# 模擬振動訊號
np.random.seed(42)
t = np.linspace(0, 100, 3000)
signal = np.sin(t) + np.random.normal(0, 0.05, size=3000)
signal[1500:1520] += np.random.normal(0, 0.6, size=20)   # 異常突波
signal[2600:2630] += 0.8                                  # 異常偏移

def make_sequences(data, window=30):
    return np.array([data[i:i+window] for i in range(len(data) - window)])

normal_part = signal[:1400]
sequences = make_sequences(normal_part).reshape(-1, 30, 1)

model = keras.Sequential([
    layers.LSTM(32, input_shape=(30, 1)),
    layers.RepeatVector(30),
    layers.LSTM(32, return_sequences=True),
    layers.TimeDistributed(layers.Dense(1)),
])
model.compile(optimizer="adam", loss="mae")
model.fit(sequences, sequences, epochs=10, batch_size=32, verbose=0)

val_sequences = make_sequences(signal[1400:1500]).reshape(-1, 30, 1)
val_recon = model.predict(val_sequences, verbose=0)
val_error = np.mean(np.abs(val_sequences - val_recon), axis=(1, 2))
tau = val_error.mean() + 3 * val_error.std()
print(f"異常門檻 τ = {tau:.4f}")

test_sequences = make_sequences(signal).reshape(-1, 30, 1)
test_recon = model.predict(test_sequences, verbose=0)
test_error = np.mean(np.abs(test_sequences - test_recon), axis=(1, 2))
anomaly_idx = np.where(test_error > tau)[0]
print(f"偵測到 {len(anomaly_idx)} 個異常序列")

plt.plot(signal, label="原始訊號")
plt.scatter(anomaly_idx, signal[anomaly_idx], color="red", s=10, label="偵測到的異常")
plt.legend()
plt.show()
```

**延伸練習**：把異常突波的振幅調小（例如只加 0.2 而不是 0.8），觀察模型還能不能偵測到——這能讓你體會「訊號強度」與「偵測靈敏度」之間的關係，也是論文提到「閾值校準」需要仔細拿捏的原因。

**管理意涵**：這個練習讓「非監督式異常偵測」不再是一個抽象名詞——各位親眼看到模型完全沒被告知「哪裡異常」，純粹靠「這段訊號重建得好不好」就抓出了不正常的區段，這正是論文標題「Hybrid」（混合式）架構中，非監督式那一半的核心價值：不需要昂貴的人工標註異常資料，也能做到早期預警。
