## Part 1｜主題課程：AI Agent 的運作邏輯與商業案例

### 一、從「回答問題」到「執行任務」

過去的人工智慧，大多是「被動工具」——需要人類下指令才會回應：我們輸入問題，它才給答案；我們上傳圖片，它才進行分析。**AI 代理人（AI Agent）**則是能夠理解目標、規劃步驟，並自動執行一連串行動的智慧系統。它不需要人類每一步都下指令，而是依照使用者設定的目標，自主完成任務。

AI Agent 的核心能力可拆解為三個環節：

| 環節 | 說明 |
|---|---|
| **目標理解** | 理解使用者提出的最終目標（例如「在九點前到達會議地點」），而不只是單一問題 |
| **任務拆解** | 把複雜目標拆解成多個可執行的子步驟 |
| **工具調用** | 呼叫外部工具（搜尋引擎、計算程式、資料庫、其他系統 API）完成各個子步驟，並將結果整合 |

### 二、案例一：智慧交通中的 AI Agent

當使用者提出「在九點前到達會議地點」這類目標時，系統會自動分析使用者的通勤習慣、時間彈性與可接受成本，同時即時蒐集道路車流、交通情況與氣象資訊，動態規劃最合適的移動方案。當地面交通壅塞時，AI 代理人可能自動調整策略，改採混合載具模式（結合地面交通與空中接駁工具），全程監控風速、雲層高度與空域流量，動態調整航道與時段。

**這個案例展現了 Agent 的關鍵特質**：使用者不需要分別查詢路況、切換不同交通 App、處理付款與預約細節——這些原本需要人類一步步操作的環節，由 AI 在背景中自主完成整合與調度。人類只需要「提出需求、確認結果」，AI 則負責「感知環境、評估風險、執行決策」。

### 三、案例二：企業會議自動化中的 AI Agent

企業會議結束後，往往伴隨大量行政工作：逐字稿整理、重點摘要、與會人員確認、通知信件撰寫、後續任務追蹤與分派。AI Agent 在這個場景中的運作流程：

1. **語音轉文字**：會議錄音檔轉換為逐字稿，保留每位發言者的內容
2. **資料擷取**：從逐字稿辨識並整理出會議日期、地點、討論主題、決議事項與待辦任務，轉換為結構化資料
3. **跨系統比對**：匯入會議通知單與員工資料表，比對逐字稿中的發言紀錄與原訂與會名單，確認實際出席人員，自動連結對應的部門與聯絡方式
4. **自動產出與寄送**：產生標準格式的會議紀錄文件，依與會人員名單自動撰寫並寄送電子郵件；若會議中指派了特定任務，系統會將相關內容標註於摘要中，作為後續追蹤依據

**管理意涵**：這個案例的價值不在於「取代討論與決策本身」，而在於協助處理會後大量重複性的行政工作——原本需要多人長時間完成的工作，得以在短時間內自動完成，特別適合企業內部會議、專案討論與跨部門協作情境。

### 四、AI Agent 的治理考量

AI Agent 能夠自主規劃並執行多步驟任務，這也帶來更高層次的治理問題（呼應第 2 週前沿安全的討論）：如何確保 Agent 的目標與人類意圖一致？當 Agent 需要調用多個外部系統（例如自動發送郵件、自動下單）時，出錯的影響範圍會比單純的問答系統更大，因此企業導入 Agent 應用時，通常會在關鍵決策節點（例如涉及金錢交易、對外溝通）保留人工確認，而不是讓 Agent 完全自主執行。

## Part 2｜Vibe Coding 實作演練：設計一個簡化的多步驟 Agent 工作流程

### 範例①　用提示詞模擬「任務拆解」的過程

**題目定義**：不需要真正串接外部系統，用提示詞練習「把一個複雜目標拆解成可執行步驟」的 Agent 思維方式。

**給 AI 的提示詞：**
```
你現在扮演一個 AI 代理人，我的目標是：
「幫我準備下週三跟重要客戶的提案會議，包含資料蒐集、簡報製作、
會前提醒。」

請你：
1. 把這個目標拆解成 5-8 個具體的子任務，並排出執行順序
2. 針對每個子任務，說明「理想情況下」需要呼叫哪些外部工具或系統
   （例如：CRM 系統查詢客戶歷史、搜尋引擎查競品資訊、
   簡報生成工具、行事曆系統發送提醒）
3. 標示出哪些子任務「必須由人類確認後才能執行」，哪些可以完全自動化
```

### 範例②　用 Python 模擬一個簡易的多步驟自動化流程

**題目定義**：用一個簡化的程式範例，體驗 Agent「感知 → 決策 → 執行」的基本架構邏輯（不需要真的串接外部 API，用模擬資料呈現流程）。

**給 AI 的提示詞：**
```
請用 Python 幫我模擬一個簡化的「會議紀錄自動化 Agent」流程：
1. 給定一段模擬的會議逐字稿文字（可自行編寫，包含至少 2 項待辦任務）
2. 寫一個函式，從逐字稿中擷取「待辦任務」與「負責人」
   （可用簡單的關鍵字比對，例如偵測「請」「負責」等字詞後面的內容）
3. 把擷取到的待辦任務整理成一份結構化的會議紀錄（用字典或表格呈現）
4. 模擬「寄送提醒信」的步驟：印出「已將以下任務提醒寄送給 [負責人]」
   （不需要真的寄信，用 print 模擬即可）
請給我可以在 Google Colab 直接執行的完整程式碼。
```

**延伸練習**：把逐字稿換成更複雜、包含多位發言者與多項任務的版本，觀察簡單的關鍵字比對方法在哪些情況下會抓錯或漏抓——這正是真實企業導入 Agent 系統時，需要搭配更精準的 NLU 技術（呼應第 10 週）來改善的地方。

**管理意涵**：這兩個練習具體呈現了 Agent 系統的核心邏輯——把一個大目標拆解成小步驟，每個步驟呼叫適當的工具，並在需要時保留人工確認的節點。理解這個邏輯，有助於在評估市售 Agent 產品時，問出「這個系統的哪些步驟是真的自動化，哪些其實還需要人工介入」這類關鍵問題。

## Part 3｜跨系統 Agent 工作流程設計工作坊

**目標**：針對自己企業一項重複性的行政審批或跨部門流程，設計一套 AI Agent 工作流程。

**操作步驟：**
1. 選定一項目前仰賴人工、跨多個系統或部門的重複性流程（例如請假簽核、採購申請、客訴處理）。
2. 用 Part 2 範例①的方法，把流程拆解成子任務，標示需要呼叫的系統。
3. 標示哪些節點必須保留人工確認。
4. 討論導入後可能節省的時間，以及最大的實施障礙。
