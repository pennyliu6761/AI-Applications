## Part 1｜主題課程：金融科技的演進與 AI 的角色

### 一、什麼是金融科技（FinTech）

金融科技（FinTech）是「金融（Finance）」與「科技（Technology）」的組合，簡單來說就是用現代科技提供或改善金融服務。這個概念約從 2000 年後興起，隨著網路、智慧型手機與雲端技術普及，人們不用到銀行就能完成許多金融操作，常見應用包括行動銀行、行動支付、P2P 借貸平台、投資管理 APP 與線上保險服務。

**AI 在 FinTech 中的角色**：提升客戶服務品質（聊天機器人客服）、分析貸款申請人的信用狀況、即時偵測可疑交易防止詐騙、快速分析大量數據協助投資與風險管理決策。台灣的銀行也已廣泛應用，例如永豐銀行「智慧小豐」AI 客服、台新銀行 Richart 依風險偏好自動推薦投資組合、台灣銀行與國泰世華導入 AI 監控交易安全。

### 二、FinTech 的四個發展階段

| 階段 | 年代 | 重點 |
|---|---|---|
| FinTech 1.0 | 1866–1967 | 金融基礎設施建設，如跨大西洋電纜、電報遠端支付 |
| FinTech 2.0 | 1967–2008 | 金融服務電子化，ATM 誕生、電子交易平台、網路銀行興起 |
| FinTech 3.0 | 2008–2018 | 智慧手機與社群媒體興起，行動支付、P2P 借貸、大數據與機器學習信用評分 |
| FinTech 4.0 | 2018 至今 | 全面數位轉型與智慧自動化，AI、物聯網、區塊鏈整合，去中心化金融（DeFi）興起 |

這個演進脈絡說明：AI 在金融領域的角色，是從「電子化交易的輔助工具」逐漸走向「主動參與風險判斷與決策」的核心引擎。

### 三、P2P 借貸與信用風險管理

P2P 借貸（Peer-to-Peer Lending）透過線上平台直接連接借款人與貸款人，省去傳統銀行作為中介的角色，讓借貸更快速便利。然而，這也讓「信用風險管理」成為最核心的挑戰——如何有效預測哪些借款人可能會違約？

用於預測違約的資料，通常包含：

| 欄位類型 | 範例 |
|---|---|
| 傳統金融指標 | 個人信用評分（FICO）、年收入、負債收入比、信用使用天數 |
| 非傳統資訊 | 就業情況、教育背景、貸款用途 |

**FICO 信用分數**：一種綜合信用歷史、負債水準、信用使用狀況等因素計算出的分數，分數越高代表信用風險越低，是美國金融機構最常用的信用評估依據之一。

## Part 2｜Vibe Coding 實作演練：P2P 借貸違約風險分析

延續教科書個案「金融信用風險管理」的精神——這個案例本身就是示範如何用提示詞驅動生成式 AI 完成資料分析，以下範例延續同樣的操作方式。

### 範例①　客戶分析：收入、FICO、負債比如何影響違約

**題目定義**：用真實的 P2P 借貸資料集，分析收入（log.annual.inc）、信用評分（fico）、負債收入比（dti）與是否違約（not.fully.paid）之間的關係，找出高風險客群的輪廓。

**資料來源（真實公開資料，可直接下載）：**
<https://raw.githubusercontent.com/shoaibb/Decision-Trees/master/loan_data.csv>

**給 AI 的提示詞：**
```
你是一位專業的資料科學家。我們要用 P2P 借貸資料集分析客戶的違約風險。
請用 Python 幫我做以下事情：
1. 讀取這個網址的 CSV 資料：
   https://raw.githubusercontent.com/shoaibb/Decision-Trees/master/loan_data.csv
2. 整理這份資料集的欄位字典，用表格說明每個欄位的意義
3. 分別比較「有違約（not.fully.paid=1）」與「無違約（not.fully.paid=0）」
   兩組客戶，在 fico（信用分數）、log.annual.inc（收入）、dti（負債收入比）
   三個欄位上的平均值差異
4. 用箱型圖（boxplot）視覺化這三個欄位在兩組客戶之間的分布差異
請給我可以在 Google Colab 直接執行的完整程式碼。
```

**預期產出的程式碼骨架：**
```python
import pandas as pd
import matplotlib.pyplot as plt
import seaborn as sns

url = "https://raw.githubusercontent.com/shoaibb/Decision-Trees/master/loan_data.csv"
df = pd.read_csv(url)

print(df.groupby("not.fully.paid")[["fico", "log.annual.inc", "dti"]].mean())

fig, axes = plt.subplots(1, 3, figsize=(15, 4))
for ax, col in zip(axes, ["fico", "log.annual.inc", "dti"]):
    sns.boxplot(x="not.fully.paid", y=col, data=df, ax=ax)
    ax.set_title(col)
plt.tight_layout()
plt.show()
```

**延伸練習**：加入 purpose（貸款用途）欄位，用 `df.groupby("purpose")["not.fully.paid"].mean()` 算出不同貸款用途的違約率，找出風險最高與最低的用途類別。

### 範例②　訓練違約預測模型，並模擬「借貸政策」的門檻設定

**題目定義**：接續範例①的資料，訓練一個分類模型預測是否違約，並延續第 4 週學過的「決策門檻」概念，模擬不同核貸門檻對放款量與壞帳率的影響。

**給 AI 的提示詞：**
```
接續前面的 P2P 借貸資料，請幫我做以下事情：
1. 用 fico、log.annual.inc、dti、int.rate、revol.util 作為特徵，
   not.fully.paid 作為預測目標，訓練一個隨機森林分類模型
2. 印出模型的準確率、精確率、召回率
3. 取得模型預測「會違約」的機率，測試從 0.3 到 0.7、間隔 0.1 的門檻，
   針對每個門檻計算：在這個門檻下會核准放款的申請人數、
   以及這些核准案件中實際違約的比例（壞帳率）
4. 印出結果表格，方便我判斷要把核貸門檻設在哪裡
請給我可以在 Google Colab 直接執行的完整程式碼。
```

**延伸練習**：思考——如果把門檻設得很嚴格（幾乎不放款給任何有風險的人），公司的放款量會大幅下降；如果設得很寬鬆，壞帳率會上升。這跟第 4 週信用卡詐騙的「決策門檻權衡」邏輯完全一致——只是這次的商業代價變成「少賺利息收入」vs.「承擔壞帳損失」。

**管理意涵**：這正是教科書個案想傳達的核心——生成式 AI 不是取代資料科學家，而是讓沒有寫程式背景的經理人，也能透過清楚的提示詞，直接參與資料分析與政策模擬的過程，加快決策速度。
