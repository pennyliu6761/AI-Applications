## 理論基礎篇

### 3.1 從文字探勘到生成式 AI：本課程方法論脈絡之終點與交會

第 13 週介紹之主題模型與情緒分析，讓機器能夠「理解」文字資料中蘊藏的結構化語意訊息（主題分布、情感傾向）；本週介紹之生成式 AI 決策系統，則進一步讓機器能夠「運用」這些理解，**主動生成具體、可執行之決策建議文字**，這是本課程「決策智能」定位下，資訊處理能力的最終進化階段——從「理解資料」（第一、三模組之統計推論與機器學習）、「輔助決策」（第二模組之知識驅動決策科學），到本週「生成決策」（大型語言模型直接產出決策建議文本）。

然而，大型語言模型雖然具備強大的語言生成能力，卻存在一項根本限制：其知識完全來自訓練資料，**無法得知企業內部特有之規章制度、最新政策文件等「私有知識」**，且訓練資料存在知識截止日期，難以掌握最新資訊。**檢索增強生成（Retrieval-Augmented Generation, RAG）**由 Lewis 等人（2020，發表於 *NeurIPS*，見本週參考文獻）提出，正是為了解決此一限制而發展的架構——讓 LLM 在生成回應之前，先從外部知識庫中檢索出與問題相關之具體文件內容，再將這些檢索結果一併納入生成過程的參考依據，使 LLM 之決策建議能夠立基於企業實際文件內容，而非僅憑訓練時記憶的一般性知識生成回應。

### 3.2 語意嵌入空間：從詞向量到句向量

第 13 週介紹之 TF-IDF 詞向量，本質上是一種**稀疏向量（sparse vector）**表徵——向量維度等同詞彙表大小，且僅在該文件實際出現之詞彙位置有非零數值，此種表徵方式無法捕捉詞彙間之語意相似關係（例如「溫室氣體」與「碳排放」在 TF-IDF 向量空間中，因為是不同的詞彙，會被視為完全無關，即使兩者語意高度相關）。

**語意嵌入（Semantic Embedding）**技術，透過在大規模文本語料上訓練之深度學習模型（如 Sentence-BERT，見本週參考文獻），將每一段文字（可以是詞彙、句子或段落）映射至一個**低維度、稠密（dense）之連續向量空間**，使得**語意相近的文字，在此向量空間中的位置也彼此靠近**——即使兩段文字沒有共用任何相同詞彙。這正是本週提示詞實作中，能夠讓「員工在家遠端連線公司系統的規定」此一口語化提問，正確檢索到「遠端工作規範規定員工於公司網路以外環境存取內部系統」此一用詞不同、但語意高度相關之政策文件的技術關鍵，也是語意嵌入相較第 13 週 TF-IDF 詞向量之核心方法論優勢——後者僅能捕捉「字面上的詞彙重疊」，前者能捕捉「深層的語意關聯」。

### 3.3 向量相似度檢索：餘弦相似度

在語意嵌入空間中，衡量兩段文字語意相似程度之標準做法，是計算其嵌入向量間之**餘弦相似度（Cosine Similarity）**：

$$
\text{Cosine Similarity}(A, B) = \frac{A \cdot B}{\|A\| \|B\|} = \frac{\sum_{i=1}^{n} A_i B_i}{\sqrt{\sum_{i=1}^{n} A_i^2} \sqrt{\sum_{i=1}^{n} B_i^2}}
$$

餘弦相似度衡量的是兩個向量之間的「夾角」大小，而非其長度差異——數值介於 -1 到 1 之間（若向量元素皆為非負值，如本週常用之嵌入模型輸出，則實務上多介於 0 到 1 之間），數值越接近 1，代表兩段文字之語意方向越一致、越相似。**RAG 系統之檢索階段，本質上就是計算使用者查詢語句之嵌入向量，與知識庫中每一份文件片段嵌入向量之餘弦相似度，並依相似度高低排序，取出最相關之前 $K$ 份文件片段（Top-K Retrieval）**，這正是本週提示詞實作「將 Top-3 相關文本結合 Context 送入 LLM」之技術基礎。

### 3.4 RAG 架構原理：檢索與生成的兩階段管道

完整的 RAG 系統，由以下核心元件構成：

1. **知識庫建構（Knowledge Base Construction）**：將企業文件（如內控規章、資安政策 PDF）切分為適當大小之文字區塊（chunks），並將每個區塊轉換為語意嵌入向量，儲存於**向量資料庫（Vector Database）**中（如業界常用之 FAISS、Chroma、Pinecone，或本週教學示範採用之記憶體內向量陣列）。
2. **檢索階段（Retrieval）**：使用者提出查詢問題後，將查詢語句同樣轉換為嵌入向量，與知識庫中所有文件區塊之嵌入向量計算餘弦相似度，取出相似度最高之前 $K$ 份文件區塊。
3. **提示詞組裝（Prompt Assembly）**：將檢索所得之文件區塊內容，連同原始使用者問題，依特定範本組裝為完整的提示詞（見理論篇 3.6 節）。
4. **生成階段（Generation）**：將組裝完成之提示詞送入大型語言模型，由模型依據提供之上下文內容生成回應，並可要求模型於回應中標註其答案所依據之具體來源文件。

**LangChain 與 LlamaIndex**（見本週參考文獻）是目前業界最廣泛使用之 RAG 應用開發框架，提供了文件載入、分塊、嵌入、向量資料庫串接、提示詞範本管理等一系列標準化元件，大幅降低企業建構 RAG 系統之開發門檻，這正是本週提示詞實作「使用 LangChain/LlamaIndex 串接企業規章 PDF 構建向量知識庫」之技術脈絡。

### 3.5 決策幻覺與其抑制策略

**決策幻覺（Hallucination）**是大型語言模型應用於企業決策情境時最受關注之風險——模型可能生成語氣流暢、看似合理，實際上卻缺乏事實依據、甚至完全捏造之內容，若決策者未經查核便直接採信此類生成內容，可能導致嚴重之決策失誤。RAG 架構透過以下機制有效抑制此一風險：

1. **提供具體上下文依據**：模型之生成內容有明確的檢索文件內容可供參照、而非僅憑訓練記憶生成，大幅降低憑空捏造事實之機率。
2. **要求來源引註（Source Citation）**：透過提示詞策略（見理論篇 3.6 節），要求模型於生成答案時，明確標註其論述依據之具體文件來源，使決策者能夠自行查核驗證，此一設計亦回應本週延伸方向所探討之演算法問責與合規稽核需求。
3. **設計拒答機制（Refusal Mechanism）**：明確指示模型，若檢索結果與使用者問題之相關性不足（如檢索相似度低於預設門檻），應誠實告知「現有知識庫中未查得相關規定」，而非勉強依據不相關之檢索內容生成看似合理實則錯誤之答案。

值得特別澄清之方法論觀念：RAG 架構能夠**顯著降低**幻覺風險，但**無法完全消除**此一風險——模型仍可能誤解檢索到的正確文件內容、或在整合多份檢索文件時產生邏輯謬誤，因此正式企業應用場景中，仍應保留人工複核機制，而非將 RAG 系統之生成建議視為可完全自動化、無需人工把關之決策依據，此一觀點與本週延伸研究方向之核心倫理考量直接呼應。

### 3.6 提示詞策略設計

**RAG 提示詞範本（Prompt Template）**之標準結構，通常包含以下組成部分：

```
【角色設定】你是一位企業內控合規稽核顧問，僅能依據下方提供之參考文件回答問題。

【參考文件】
[文件1標題]：[文件1內容]
[文件2標題]：[文件2內容]
[文件3標題]：[文件3內容]

【使用者問題】[使用者實際提問]

【回答要求】
1. 僅依據上方參考文件內容作答，不得引用參考文件以外之知識。
2. 若參考文件內容不足以回答問題，請明確告知「現有文件未涵蓋此問題」，不得臆測作答。
3. 回答時請明確標註所依據之文件編號。
```

此一結構化提示詞設計，明確界定了模型之「角色」「可用資訊範圍」「回應格式要求」與「不確定情境之因應方式」，是本週提示詞實作要求「將 Top-3 相關文本結合 Context 送入 LLM 生成具備來源引註的決策建議」之具體實踐方式。不同的提示詞策略設計（如是否要求逐步推理、是否限制回答字數、是否要求列點呈現），可能對生成答案之品質與決策實用性產生顯著影響，這也是本週理論篇 3.7 節與 Colab 實作將進行系統化比較之重點。

### 3.7 RAG 系統之評估指標

完整的 RAG 系統評估，應分別從**檢索品質**與**生成品質**兩個層面進行：

**檢索品質評估**：
- **檢索相似度分數**：檢視 Top-K 檢索結果之相似度數值分布，數值過低可能代表知識庫涵蓋範圍不足或查詢語句表達方式與知識庫用詞差異過大。
- **檢索準確率（Retrieval Precision）**：若有標註好之「問題—正確答案文件」配對資料集，可計算模型是否成功將正確文件納入 Top-K 檢索結果中。

**生成品質評估**：
- **答案準確度評分**：可採人工評分（由領域專家依「事實正確性」「完整性」「來源引註正確性」等面向評分），或設計自動化評分規則（如檢查生成答案中引註之文件編號，是否確實為檢索階段排序最高之相關文件）。
- **幻覺發生率**：檢視生成答案中，是否存在無法從檢索文件內容中找到依據之陳述。

本週提示詞實作要求「計算答案準確度評分」，即對應此處生成品質評估之核心工作，正式研究中建議至少納入人工評分機制，而非僅依賴自動化規則，因自動化規則難以完整捕捉語意層次之事實正確性判斷。

### 3.8 論文中 RAG／LLM Agent 章節的標準寫法架構

1. **知識庫建構說明**：文件來源、分塊策略、嵌入模型選擇。
2. **檢索管道設計**：Top-K 設定、相似度門檻設定依據。
3. **提示詞策略設計與版本比較**：若比較多種提示詞策略，應列出各版本之具體設計差異。
4. **檢索相似度熱圖**：呈現多組測試問題之檢索結果相似度分布。
5. **生成答案品質評估表**：不同提示詞策略下之答案準確度、來源引註正確性比較。
6. **個案示範**：呈現至少一則完整之「問題—檢索結果—生成答案」示範案例。
7. **系統限制與人工複核機制討論**。

## 研究設計實例：企業內部資安合規政策與內控制度之智慧稽核問答系統效益評估

### 4.1 研究背景與動機

企業內部資安合規政策與內控制度文件，數量龐大且條文用語專業，員工在實務執行時，經常難以快速查找到適用之具體規定，傳統做法仰賴人工查閱厚重之政策手冊或詢問稽核人員，效率不彰。本研究運用 RAG 架構，建構一套企業級智慧稽核問答系統，讓員工得以自然語言提問，系統自動檢索相關政策條文並生成具備來源引註之決策建議，同時評估此一系統相較傳統查閱方式之效益。

### 4.2 研究目的

1. 建構涵蓋資安、內控、採購、差勤等企業規章之向量知識庫。
2. 設計並比較不同提示詞策略對生成答案品質之影響。
3. 評估系統之檢索準確度與生成答案之來源引註正確性。
4. 探討此類智慧問答系統，對提升員工合規查詢效率之潛在效益。

### 4.3 研究對象與資料來源

建議以特定企業實際之內部規章制度文件（如員工手冊、資安管理辦法、內控作業程序）為研究對象，並蒐集一批具代表性之常見員工提問，作為系統效能評估之測試問題集。本課程範例為教學示範，模擬八份涵蓋資安、內控、個資保護、差勤、採購、供應商管理等主題之企業規章條文片段，作為知識庫內容。

### 4.4 資料分析流程規劃

```
蒐集企業內部規章制度文件
        │
        ▼
文件分塊（Chunking）：切分為適當大小之知識單元
        │
        ▼
以語意嵌入模型將各知識單元轉換為向量，建構向量知識庫
        │
        ▼
設計測試問題集（模擬員工常見查詢情境）
        │
        ▼
【檢索階段】計算查詢與知識庫之餘弦相似度，取 Top-K 相關文件
        │
        ▼
繪製檢索相似度熱圖，檢視檢索品質
        │
        ▼
設計多組提示詞策略（如：基礎版、要求逐步推理版、要求列點版）
        │
        ▼
【生成階段】將 Top-K 文件結合提示詞範本送入 LLM 生成回答
        │
        ▼
評估各提示詞策略之答案準確度與來源引註正確性
        │
        ▼
撰寫研究結果與智慧稽核問答系統效益討論
```

### Step 2：查詢語意檢索

```python
# ============================================================
# Cell 2：查詢語意檢索
# ------------------------------------------------------------
# 提示詞實作對照（前置步驟）：
# 「搭建 RAG 檢索管道」
# ============================================================

def retrieve_top_k(query, k=3):
    """
    對使用者查詢執行語意檢索，回傳相似度最高之前 K 份文件。
    """
    query_embedding = embedding_model.encode([query])
    similarities = cosine_similarity(query_embedding, document_embeddings).flatten()

    top_k_idx = similarities.argsort()[::-1][:k]
    results = kb_df.iloc[top_k_idx].copy()
    results['similarity'] = similarities[top_k_idx]
    return results.reset_index(drop=True)

test_query = "如果員工要在家裡遠端連線公司系統，有什麼資安規定要遵守？"
retrieval_result = retrieve_top_k(test_query, k=3)

print(f"查詢：{test_query}\n")
print("=== 表 1：Top-3 檢索結果 ===")
display(retrieval_result[['id', 'title', 'similarity', 'content']].round(4))
```

### Step 4：RAG 提示詞組裝

```python
# ============================================================
# Cell 4：RAG 提示詞組裝
# ------------------------------------------------------------
# 提示詞實作對照：
# 「將 Top-3 相關文本結合 Context 送入 LLM 生成具備來源引註
#   的決策建議。」
# ============================================================

def build_rag_prompt(query, retrieved_docs, strategy='basic'):
    """
    依指定策略組裝 RAG 提示詞。

    strategy 選項：
    - 'basic': 基礎版，僅要求依文件作答並標註來源
    - 'stepwise': 要求先列出判斷依據，再給出結論
    - 'structured': 要求以結構化列點格式回答
    """
    context = "\n".join([
        f"[{row['id']}：{row['title']}] {row['content']}"
        for _, row in retrieved_docs.iterrows()
    ])

    base_instruction = (
        "你是一位企業內控合規稽核顧問，僅能依據下方提供之參考文件回答問題。"
        "若參考文件內容不足以回答問題，請明確告知「現有文件未涵蓋此問題」，不得臆測作答。"
        "回答時請標註所依據之文件編號。"
    )

    if strategy == 'stepwise':
        base_instruction += "請先列出你判斷所依據的具體條文重點，再給出最終結論。"
    elif strategy == 'structured':
        base_instruction += "請以條列式（1. 2. 3.）格式呈現回答重點。"

    prompt = f"""{base_instruction}

【參考文件】
{context}

【使用者問題】{query}
"""
    return prompt

rag_prompt = build_rag_prompt(test_query, retrieval_result, strategy='basic')
print("=== 組裝完成之 RAG 提示詞 ===\n")
print(rag_prompt)
```

### Step 5：呼叫 LLM 生成具來源引註之回答

```python
# ============================================================
# Cell 5：呼叫大型語言模型生成回答
# ------------------------------------------------------------
# 說明：以下示範透過 Anthropic API 呼叫 Claude 模型完成生成
# 階段。Colab 中請先於左側「密鑰」（Secrets）面板設定名為
# ANTHROPIC_API_KEY 之金鑰，再以下方方式安全讀取，切勿將
# 金鑰直接寫入程式碼中。
# ============================================================

!pip install anthropic --quiet

import anthropic
from google.colab import userdata

client = anthropic.Anthropic(api_key=userdata.get('ANTHROPIC_API_KEY'))

def generate_rag_answer(prompt, model="claude-sonnet-4-6"):
    response = client.messages.create(
        model=model,
        max_tokens=800,
        messages=[{"role": "user", "content": prompt}]
    )
    return response.content[0].text

answer = generate_rag_answer(rag_prompt)
print("=== LLM 生成之具來源引註回答 ===\n")
print(answer)
```

### Step 6：多組提示詞策略之答案品質比較

```python
# ============================================================
# Cell 6：多組提示詞策略比較
# ------------------------------------------------------------
# 提示詞實作對照：
# 「不同 Prompt 策略之決策品質評估表。」
# ============================================================

strategies = ['basic', 'stepwise', 'structured']
strategy_results = []

for strategy in strategies:
    prompt = build_rag_prompt(test_query, retrieval_result, strategy=strategy)
    generated_answer = generate_rag_answer(prompt)

    # 自動化檢核：答案中是否正確引用了 Top-1 檢索文件之編號
    top1_doc_id = retrieval_result.iloc[0]['id']
    citation_correct = top1_doc_id in generated_answer

    strategy_results.append({
        '策略': strategy,
        '答案長度': len(generated_answer),
        '是否正確引註Top-1文件': citation_correct,
        '答案內容（前100字）': generated_answer[:100] + '...'
    })

strategy_comparison = pd.DataFrame(strategy_results)
print("=== 表 3：不同提示詞策略之決策品質評估表 ===")
display(strategy_comparison)

print("\n提醒：本表之「是否正確引註」為自動化規則檢核，正式研究應搭配")
print("人工評分（事實正確性、完整性、可讀性）以獲得更完整之答案品質評估。")
```

### Step 7：檢索失敗情境模擬（拒答機制測試）

```python
# ============================================================
# Cell 7：檢索失敗情境模擬——測試拒答機制
# ------------------------------------------------------------
# 教學目的：測試當使用者提問超出知識庫涵蓋範圍時，系統是否
# 能正確觸發拒答機制，而非勉強生成看似合理卻缺乏依據之答案，
# 此為理論篇 3.5 節「決策幻覺抑制策略」之具體驗證。
# ============================================================

out_of_scope_query = "公司的員工旅遊補助金額上限是多少？"
oos_retrieval = retrieve_top_k(out_of_scope_query, k=3)

print(f"查詢：{out_of_scope_query}\n")
print("=== 檢索結果（預期相似度應普遍偏低）===")
display(oos_retrieval[['id', 'title', 'similarity']].round(4))

SIMILARITY_THRESHOLD = 0.35   # 相似度門檻，低於此值視為知識庫未涵蓋

if oos_retrieval['similarity'].max() < SIMILARITY_THRESHOLD:
    print(f"\n⚠️ 最高檢索相似度（{oos_retrieval['similarity'].max():.4f}）低於門檻 {SIMILARITY_THRESHOLD}，")
    print("系統應觸發拒答機制，回覆「現有文件未涵蓋此問題」，而非勉強生成答案。")
else:
    oos_prompt = build_rag_prompt(out_of_scope_query, oos_retrieval, strategy='basic')
    oos_answer = generate_rag_answer(oos_prompt)
    print("\n生成回答：", oos_answer)
```

> **4.1 檢索管道效能評估**
>
> 本研究建構涵蓋資安、內控、個資保護、差勤、採購、供應商管理及遠端工作規範等主題之知識庫，並設計 4 組模擬員工常見查詢情境之測試問題，評估檢索管道之效能。結果顯示，4 組測試查詢皆成功將語意上最相關之文件檢索為 Top-1 結果：「遠端連線資安規定」查詢對應「遠端工作規範」之相似度為 .32；「採購簽核層級」查詢對應「內部控制制度」之相似度為 .47；「客戶個資保存期限」查詢對應「個人資料保護作業要點」之相似度為 .42；「資安事件通報時限」查詢對應「資通安全事件通報程序」之相似度達 .60，為四組查詢中最高。四組查詢之 Top-1 相似度，皆明顯高於同一查詢對其餘不相關文件之相似度（多數趨近於 0），顯示檢索管道確實能有效區辨語意相關與不相關之文件。
>
> **4.2 拒答機制驗證**
>
> 為驗證系統之決策幻覺抑制機制，本研究進一步測試一則超出知識庫涵蓋範圍之查詢（員工旅遊補助相關問題），結果顯示，該查詢與知識庫全部文件之最高相似度僅為 .24，低於本研究設定之 .35 判斷門檻，系統應正確觸發拒答機制，避免強行依據不相關之文件內容生成看似合理卻缺乏依據之答案。此一結果印證理論篇 3.5 節所述——透過設定合理之相似度門檻並明確要求模型於證據不足時誠實告知，能有效降低生成式 AI 決策系統之幻覺風險。
>
> **4.3 提示詞策略比較**
>
> 本研究進一步比較三種提示詞策略（基礎版、逐步推理版、結構化列點版）之生成答案品質，自動化檢核結果顯示，三種策略皆正確於答案中標註了 Top-1 檢索文件之編號，顯示基本的來源引註要求，在本研究之提示詞設計下均能穩定達成；惟三種策略生成答案之詳細程度與可讀性仍有差異，正式研究建議進一步納入人工評分機制，針對事實正確性、完整性與決策實用性等面向進行更細緻之品質比較，以確立最適合企業實務導入之提示詞策略版本。

## 常見統計誤區與 Q&A

**Q1：RAG 系統的檢索階段和第 13 週學過的 TF-IDF 文件相似度計算，有什麼本質上的不同？**
兩者在「計算相似度」此一數學運算步驟上是相同的（都是計算向量間之餘弦相似度），核心差異在於「向量的來源」。第 13 週之 TF-IDF 向量，是根據詞彙在文件中「是否出現、出現幾次」之字面統計資訊建構而成，本質上是一種詞彙重疊比對機制；本週之語意嵌入向量，則是透過深度學習模型在大規模語料上訓練而得，能捕捉「意思相近但用詞不同」的深層語意關聯（如理論篇 3.2 節之「溫室氣體」與「碳排放」範例）。這也是為什麼本週提示詞實作能夠處理「口語化提問」與「正式條文用語」之間的落差，而若僅使用第 13 週之 TF-IDF 方法，檢索效果通常會因為使用者提問用詞與正式文件用詞不完全重疊，而顯著遜色於語意嵌入方法。

**Q2：RAG 系統已經有檢索機制輔助，是不是就完全不會有幻覺問題了？**
不是，這是本週理論篇 3.5 節特別澄清之重要觀念——RAG 架構能「顯著降低」幻覺風險，但無法「完全消除」。即使檢索階段成功找到了正確相關的文件，生成階段的大型語言模型，仍可能在整合、摘要多份檢索文件內容時，產生誤解原文語意、混淆不同文件內容、或過度推論原文未明確陳述之結論等問題。因此，正式企業應用場景中，RAG 系統之生成建議應被定位為「輔助決策的初步草案」，而非「可直接自動執行、無需人工複核之最終決策」，這也是本週延伸研究方向與台灣行政院生成式 AI 使用參考指引（見本週參考文獻）中，均明確強調人工複核機制不可或缺之政策考量。

**Q3：檢索相似度的門檻值（本週範例設為 0.35）該怎麼決定？**
此一門檻值之設定，並無放諸四海皆準的固定標準，應依所採用之嵌入模型特性與實際應用情境，透過實證測試校準。實務上建議之做法為：蒐集一批「已知應該被拒答」之範圍外測試問題（如本週 Step 7 之員工旅遊補助範例），以及一批「應該被正常回答」之範圍內測試問題，分別計算兩組問題之最高檢索相似度分布，觀察兩組分布是否存在可清楚區隔之數值區間，並將門檻值設定於此區間之間，而非隨意選定一個數字。若兩組問題之相似度分布高度重疊、難以找到清楚的區隔點，則可能顯示現有嵌入模型或知識庫內容之區辨能力仍有待改善。

**Q4：本週的「答案準確度評分」用自動化規則檢查是否有引用正確文件編號，這樣的評估方式足夠嗎？**
不夠完整，這是本週理論篇 3.7 節與 Step 6 程式碼註解中特別提醒之重點。自動化規則檢核（如檢查答案文字中是否包含正確之文件編號字串）僅能驗證「格式層次」之來源引註是否存在，無法驗證「內容層次」之事實正確性——模型可能正確標註了文件編號，但對該文件內容之摘要或詮釋卻存在事實錯誤或斷章取義之情形。正式研究中，建議至少抽樣一部分生成答案，由具備領域知識之人員（如企業內部稽核人員）進行人工評分，涵蓋事實正確性、完整性、可讀性等多個面向，方能獲得具有學術與實務參考價值之答案品質評估結論，這也是本課程第 9 週以來反覆強調之「自動化指標應搭配人工判斷，而非單獨依賴」方法論原則之延續體現。

**Q5：如果企業的內部規章文件非常多（例如上千頁），本週示範的簡單向量陣列檢索方式還夠用嗎？**
本週為教學示範，採用僅有 8 份文件之小型知識庫，直接以 `numpy` 陣列儲存嵌入向量、並以窮舉方式計算餘弦相似度，這在小規模知識庫下運算效率完全足夠；但若企業知識庫規模達到數千甚至數萬份文件片段，窮舉式相似度計算之效率將顯著下降，此時應改用專業之**向量資料庫（Vector Database）**（如 FAISS、Chroma、Pinecone 等），這些工具透過近似最近鄰（Approximate Nearest Neighbor, ANN）演算法，能在大規模向量集合中快速找出近似最相關之結果，同時仍能維持良好之檢索品質，這正是本週理論篇 3.4 節提及 LangChain、LlamaIndex 等框架，通常會搭配專業向量資料庫一併使用之實務考量，有興趣進行大規模知識庫期末專題之學生，可進一步查閱這些工具之官方文件。

## 延伸研究方向：導入生成式 AI 輔助決策系統對管理階層決策速度與品質之實證影響研究

### 6.1 研究背景與理論基礎

企業導入生成式 AI 輔助決策系統（如本週示範之 RAG 智慧稽核問答系統），除了技術層面之檢索與生成效能評估外，更值得關注的是其對管理階層實際決策行為之影響——是否確實提升了決策速度？是否在決策品質上有可衡量之改善？或是否引發員工對 AI 決策建議之過度依賴風險？本週參考文獻中之台灣本土 AI 應用文章已指出，RAG 系統之來源引註設計，能大幅降低合規審查之難度、提升使用者信任，此為本延伸研究方向之重要理論基礎。

### 6.2 建議研究設計

1. **理論框架**：可結合本課程第 2 週所學之 UTAUT2 科技接受模型，探討管理階層對生成式 AI 決策輔助系統之採用意願前因；並可設計準實驗研究（如同一決策情境，比較「有無 AI 輔助」兩組決策時間與品質之差異），檢驗系統導入之實證效益。
2. **候選衡量指標（範例）**：
   - 決策時間：完成特定決策任務（如查核某項採購案是否符合內控規定）所需時間
   - 決策品質：由資深主管或稽核專家評分決策建議之正確性與完整性
   - 系統信任度與採用意願：可沿用第 2 週 UTAUT2 相關量表構念
   - 決策者對 AI 建議之依賴程度：檢視決策者是否過度依賴 AI 建議、未經查證即採納
3. **研究對象**：建議以實際導入生成式 AI 決策輔助系統之企業部門主管或承辦人員為研究對象，採前後測準實驗設計或對照組設計。
4. **分析方法**：決策時間與品質差異可採第 2 週所學之統計檢定方法；系統採用意願前因可採第 1、3 週所學之量表發展與 PLS-SEM 分析；亦可整合第 9–11 週所學之機器學習方法，建構「決策品質預測模型」，探討哪些因素最能預測 AI 輔助決策系統之導入成效，充分展現本課程 14 週方法論之整合應用可能性。
5. **管理與政策實務意涵**：此類研究可為企業管理階層提供生成式 AI 決策輔助系統導入之實證效益依據，並呼應台灣行政院已發布之生成式 AI 使用參考指引（見本週參考文獻）中，關於「不得以未經確認之產出內容直接作成行政行為或作為公務決策之唯一依據」之政策原則，探討如何在效率提升與決策風險控管間取得平衡。

### 6.3 給學生的思考練習

回顧本課程 14 週之完整學習旅程：從第 1 週量表建構與信效度驗證，到第 3 週結構方程模型之因果路徑分析，第 4–7 週知識驅動型決策科學方法，第 8–11 週資料驅動型機器學習方法，再到本週生成式 AI 決策系統。請思考：若要研究「企業導入生成式 AI 輔助決策系統對管理階層決策速度與品質之實證影響」此一主題，你會如何整合運用本課程所學之至少三種不同方法論工具（例如：以量表發展衡量系統採用意願、以準實驗設計搭配統計檢定衡量決策績效差異、以機器學習方法探索影響採用成效之關鍵因素），設計一份完整的混合研究方法（Mixed-Methods Research）期末專題？這樣的整合能力，正是本課程「決策智能與混合式 AI」定位下，最終期望學生具備的核心素養。

### 附錄 C：常見程式錯誤排解（Debugging Tips）

| 錯誤現象 | 常見原因 | 排解建議 |
|---|---|---|
| `SentenceTransformer` 模型下載失敗或逾時 | Colab 網路環境暫時性問題，或首次下載模型檔案較大 | 重新執行下載指令，或改用更輕量之嵌入模型 |
| 呼叫 Anthropic API 時出現金鑰錯誤 | 未正確於 Colab Secrets 面板設定 `ANTHROPIC_API_KEY` | 確認已在左側鑰匙圖示面板新增金鑰，並開啟該筆記本之存取權限 |
| 檢索結果之相似度數值普遍偏低（即使是應該相關的文件） | 知識庫文件內容過於簡短或口語化程度與查詢差異過大 | 檢視文件分塊策略是否保留足夠上下文，必要時調整分塊大小 |
| 生成答案未確實標註來源文件編號 | 提示詞中之格式要求不夠明確或不夠強調 | 於提示詞中以更明確之範例格式（如「請以【文件X】格式標註」）加強指示 |
| `cosine_similarity` 計算結果維度不符預期 | 查詢與文件嵌入向量未正確 reshape 為二維陣列 | 確認 `embedding_model.encode()` 輸出已符合 `cosine_similarity()` 函式要求之輸入格式 |

## 全課程總結：14 週決策智能與混合式 AI 方法論地圖

本課程以「決策智能與混合式 AI」為核心定位，橫跨四大模組、14 週課程，建構了一套完整的量化研究方法論工具箱：

| 模組 | 週次 | 方法論家族 | 知識論基礎 | 核心產出 |
|---|---|---|---|---|
| 第一模組 | 1–3 週 | 量表發展與結構方程模型 | 資料驅動、理論驗證 | 因素結構、路徑係數、因果模型 |
| 第二模組 | 4–7 週 | 多準則決策科學 | 知識驅動、專家判斷 | 準則權重、方案排序、因果分群 |
| 第三模組 | 8–11 週 | 機器學習與混合式模型 | 資料驅動、預測導向 | 分群結構、分類預測、可解釋性分析 |
| 第四模組 | 12–14 週 | 深度學習與生成式 AI | 資料驅動、生成導向 | 時序預測、語意理解、決策建議生成 |

貫穿全課程之三條核心方法論主軸，值得學生在規劃期末專題與未來研究生涯時反覆回顧：

1. **資料驅動與知識驅動的互補（第一、二模組）**：統計推論檢驗理論假設，決策科學結構化專家判斷，兩者回答不同性質之研究問題，不存在孰優孰劣，而是依研究問題本質選用合適工具。

2. **預測準確度與可解釋性的權衡（第三模組）**：從單一決策樹到隨機森林、梯度提升機，預測效能持續提升的同時，也促使可解釋性 AI（SHAP、置換重要性）技術之同步發展，兩者應並重而非偏廢。

3. **混合式方法論整合的方法論創新（第 11、14 週）**：SEM-ANN 展現了「理論驗證」與「非線性預測補強」之整合可能；RAG 展現了「生成式 AI 之流暢表達」與「傳統資訊檢索之精確可溯源」之整合可能，這正是本課程反覆強調——真正優秀的量化研究者，應具備跨方法論靈活調度、甚至創造性整合的能力，而非固守單一方法論典範。

期末專題之規劃，鼓勵學生回顧本課程 14 週之完整方法論地圖，思考自己的研究主題最適合運用哪些方法（可能是單一方法之深入應用，也可能是跨模組之混合方法整合），並將本課程反覆示範之嚴謹研究設計原則——明確的操作型定義、適切的樣本規劃、誠實的統計限制揭露、以及論文寫作之學術規範——貫徹落實於期末專題之中。祝福各位同學在後續之研究生涯中，能靈活運用本課程所建立之決策智能與混合式 AI 方法論工具箱，產出兼具方法論嚴謹度與實務應用價值之優秀研究成果。
